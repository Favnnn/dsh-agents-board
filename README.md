# Agents board — плагин-доска для DeepSeek Harness

Плагин для web GUI DeepSeek Harness: одна панель со всеми агентами и субагентами из всех чатов —
колонки «В работе / Готово / Архив», живые счётчики (шаги, токены, контекст), карточки с
прогресс-барами и оповещения о завершении и об ожидании ответа.

- **Плагин:** `dsh-agents-board` 1.25.2
- **Harness:** dsh-v0.2.0-rc.2 (официальная доставка бандлов)
- Детали миграции со старой схемы и анализ отказоустойчивости — в [PLUGIN-FAILSAFE-REPORT.md](PLUGIN-FAILSAFE-REPORT.md).

## Установка

Требуется: установленный harness (клон репозитория с выполненным `pnpm install`). pnpm нужен
самому установщику (его уже использует harness). `%DSH_HOME%` по умолчанию `C:\<пользователь>\.dsh`,
учитывается переменная окружения `DSH_HOME`.

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

или двойной клик по **`install.bat`** (cmd-обёртка, держит окно открытым).

Установщик самодостаточен (сам находит чекаут harness; путь можно задать `-HarnessRoot`) и делает
строго по порядку:

1. Вендорит библиотеку конфиг-схемы (`schemastery` + `cosmokit`) из чекаута в `deps\` — она питает
   Config-схему, когда голое имя пакета не резолвится вне дерева harness.
2. Чистит артефакты до-бандловой схемы: маркерованный `file://`-ряд из профильного патча
   (вторичная регистрация ломает rc.2-сканер клиентских модулей) и старую копию из
   `%DSH_HOME%\plugins\dsh-agents-board\` (в rc.2 этот каталог harness'ом не используется).
3. Упаковывает папку в tarball (`pnpm pack`) и ставит бандл официальным CLI из чекаута:
   `pnpm dsh plugin --profile web add <файл.tgz>`. Ничего в файлах профиля вручную не пишется —
   dependency в манифесте, список `dsh.profile.bundles`, копия пакета в `node_modules` и
   overlay-ряд из `cordis.patch.yml` бандла создаёт сам CLI.
4. После успешной установки удаляет упакованный tarball **точечно** — по точному имени
   `<имя>-<версия>.tgz` из `package.json` (плюс ровно тот tarball, на который профиль ссылался
   раньше, если он ещё лежит). Никаких масок и нецелевых удалений. Нюанс порядка: `dsh plugin
   add` прогоняет полный `pnpm install` профиля, который резолвит все зависимости манифеста, —
   поэтому битую ссылку на отсутствующий tarball (осталась от прошлого запуска или от смены
   версии) установщик сначала снимает официальным `dsh plugin remove`; ряд при этом
   пересоздаётся из `cordis.patch.yml` бандла, кастомные значения настроек сбрасываются к
   дефолтным.

После установки перезапустите `pnpm dsh web` и обновите страницу (F5): реестр клиентских модулей
строится при старте сервера, поэтому первая загрузка плагина требует рестарта; все дальнейшие
переключения — нет.

Повторный запуск безопасен и идемпотентен. Изменили `host.mjs` / `client.js` в мастер-папке —
снова запустите `install.ps1` (профиль копирует новые байты), затем рестарт сервера (host) или
просто F5 (клиент).

## Где живёт плагин

| Что | Где | Роль |
|---|---|---|
| Мастер-папка (исходники) | папка этого README | правки, перенос; рантаймом не читается |
| Артефакт `*.tgz` | та же папка, удаляется установщиком после установки | временный носитель для `pnpm pack` |
| **Живая копия** | `%DSH_HOME%\profiles\web\node_modules\dsh-agents-board\` | её грузит harness: клиент отдаётся с `/plugins/dsh-agents-board/client.js`, host-модуль загружается отсюда |
| Регистрация | `%DSH_HOME%\profiles\web\package.json` (dependency + `dsh.profile.bundles`) | чем профиль владеет |
| Настройки | `%DSH_HOME%\profiles\web\cordis.patch.yml` — блок `config:` ряда `agents-board` | редактируется со страницы Plugins |

**Почему именно `profiles\web\node_modules\dsh-agents-board\`** — это не выбор плагина, а
архитектура rc.2, общая для всех бандлов:

1. `dsh plugin add` оформляет плагин как **dependency профиля** и запускает pnpm внутри
   `profiles\web\` — pnpm материализует любой пакет профиля в его `node_modules`. Там же лежат и
   остальные пакеты профиля; отдельного «каталога плагинов» в rc.2 нет.
2. Web-сервер раздаёт клиентские бандлы по `/plugins/<имя>/client.js` из `node_modules` профиля —
   это проверено: ревизия файла (`framedHash('plugin-artifact', …)` от stat-метаданных) совпадает
   с отдачей по HTTP 200.
3. Сканер клиентских модулей при старте собирает boot-манифест из установленных пакетов профиля
   (поля `dsh.client` в их `package.json`) — он читает ровно это место.
4. `%DSH_HOME%\profiles\web` — дом профиля (настройки, патч, `node_modules`): профиль переносится
   как единое целое, и всё, что ему нужно, лежит вместе.

**Почему копия, а не ссылка на мастер-папку:** pnpm при directory-spec ставит junction на папку —
перенос папки ломал бы работающий плагин. Tarball даёт профилю независимую копию, поэтому
мастер-папку можно в любой момент переместить, переименовать или удалить — плагин этого не
заметит. Обратная сторона: манифест профиля хранит `file:`-ссылку на tarball, который установщик
удаляет; перед любым «голым» `pnpm install` внутри профиля снова запустите `install.ps1` — он
перепакует и перепривяжет.

## Перенос на другой ПК

1. Скопируйте папку плагина в любой путь (например `C:\Tools\dsh-agents-board`).
2. На том ПК должен быть установлен harness и хотя бы раз запущен `pnpm dsh web`.
3. Запустите `install.ps1` (или `install.bat`) из скопированной папки — он сам определит своё
   расположение (`$PSScriptRoot`) и найдёт чекаут harness.
4. Перезапустите `pnpm dsh web`, обновите страницу.

## Удаление

```powershell
powershell -ExecutionPolicy Bypass -File uninstall.ps1
```

Скрипт снимает бандл официальным CLI (`pnpm dsh plugin --profile web remove dsh-agents-board` —
CLI убирает dependency, список бандлов, копию из `node_modules` и overlay-ряд) и зачищает артефакты
до-бандловой схемы: `file://`-ряд из патча, старую копию `%DSH_HOME%\plugins\dsh-agents-board\`,
раздел `agents-board` в `settings.yaml`. Мастер-папку не трогает. После удаления — рестарт
`pnpm dsh web`.

## Настройки на странице Plugins

Плагины управляются на странице **Plugins** (сайдбар → Plugins). Доска появляется там как
установленный бандл; её настройки лежат **прямо на странице бандла** (между описанием и рядами,
слот `plugins.bundle.config`). Родной тумблер ряда включает и выключает плагин целиком. Поля
действуют сразу, без перезапуска:

- **Язык доски** (`language`: auto / en / ru) — «Авто» показывает английский словарь; RU переводит
  весь текст доски.
- **Уведомлять о завершении задачи** (`notify`) — звук + тост на каждое завершение, включая
  сессию, на которую вы сейчас смотрите (собственный наблюдатель перехода «работает → закончил»;
  менеджерский бит пропускает выбранную сессию — именно из-за него звук пропадал). Завершение,
  случившееся при отключённой странице, не звонит — живой наблюдатель видит только переходы при
  подключённой странице.
- **Звук при ожидании ответа** — если агент остановился в ожидании вашего подтверждения, ревью
  плана или вопроса, звучит тот же «динь» с тостом «Агент ждёт вашего ответа»; состояние читается
  из поля `pendingInteraction` строки сессии.
- **Озвучивание через** (`sound`: Браузер / Windows + устройство / Процесс Windows) — повторяет
  dsh-text-reader: **Браузер** (страница играет wav сама; поприложенческий роутер ведёт браузер),
  **Windows + устройство** (spawn'утый помощник играет на выбранном устройстве через waveOut API
  напрямую — `waveOutOpen` на точный индекс; поток привязывается к выбранному выходу и поприложенческие
  роутеры вроде Stream Deck его не перехватывают; MCI не используется — его `open … device N` не
  работает ни для одного индекса), **Процесс Windows** (то же, но на системном дефолте через
  маппер — вот тут роутер может увести `powershell.exe` куда угодно); если браузер отказался
  играть, звонок автоматически уходит помощнику. **Устройство** — живое перечисление WinMM-устройств
  вывода на сервере (`waveOutGetDevCapsW` с точной раскладкой структуры; возвращает индексы и
  названия реальных устройств — динамики, HDMI-мониторы, цифровой выход); пустой список означает,
  что перечисление не удалось, остаётся системный дефолт; **Проба** играет один звонок текущим
  режимом.

## Что появляется в интерфейсе

- **Кнопка в сайдбаре** (`sidebar.footer.action`, внизу слева) — точка-индикатор: голубая, когда
  есть запущенные сессии, серая — иначе. Клик открывает/закрывает доску.
- **Панель-доска** (`shell.overlay`) — три колонки: **В работе** (запущенные), **Готово**
  (завершённые), **Архив** (архивные + «Скрыть показанные»). Шапка: счётчики запущенных, токенов
  за день, «ждут ответа»; перетаскивание за шапку, resize за края, позиция сохраняется в
  `localStorage` (`agents-board.layout`).
- **Карточки** — заголовок, режим, `шагов · ходов`, суммарные токены, «N мин назад», суммарное
  время LLM, строка контекста и прогресс-бар (зелёный < 60%, жёлтый 60–89%, красный ≥ 90%).
  Подсветка состояния: **жёлтая заливка** + метка «ждёт ответа» — агент остановился в ожидании
  вашего ввода (состояние `pendingInteraction` из status-снапшота сервиса `uiSession`);
  **зелёная заливка** — задача завершилась и ещё не просмотрена (гаснет после просмотра). У
  работающей задачи подсветки нет — её ведёт анимированная точка статуса. Панель непрозрачная:
  тон меню темы положен поверх непрозрачной базы, а фон вокруг затемняется маской темы.
- **Оповещения** — системный «динь» + тост над полем ввода (клик открывает сессию). Виды:
  завершение, ожидание вашего ответа, пауза на шаге-лимите. Работают при закрытой доске; тумблер
  `notify` глушит всё.

## Как это устроено

- **`host.mjs`** — host-половина на `node:`-встроенных: экспортирует Config-схему `agents-board`
  (`enabled`, `language`, `notify`, `sound`, `device` — все поля volatile, редактируются живьём) и
  маршруты web-сервера: `/agents-board/chime.wav`, `/agents-board/chime[?device=…]` (winmm/MCI,
  коалесинг залпов), `/agents-board/devices`. schemastery грузится синхронно через
  `createRequire` с фолбэком на вендоренную копию в `deps\`.
- **`client.js`** — бандл в формате ModuleLoader (`window.__ModuleLoader__`), только
  `createElement` (без JSX). Регистрирует слоты: `shell.overlay` (панель + слой тостов),
  `sidebar.footer.action` (кнопка), `plugins.bundle.config` (редактор на странице бандла).
  Каждая регистрация — через safeSlot: ошибка одной части глушит только её, не весь плагин.
  Все хуки dispatch оборачиваются проверкой существования — оболочка вправе менять их состав
  между версиями.
- **Данные** — только клиентские зеркала: сессии (состояние, проекции `sessionStats`,
  `tokenUsage`, `contextPressure`, `agentPreset`, биты `completed` и `pendingInteraction`),
  архив (`workspaces.archivedSessionIds`), ConfigForm `agents-board`. По клику с сервера ничего
  не запрашивается.

## Диагностика

- **Доски нет после установки** — перезапустите `pnpm dsh web`, F5;
  `http://127.0.0.1:3080/plugins/dsh-agents-board/client.js` должен отдаваться (не 404).
- **Кнопка и панель исчезли** — выключен тумблер «Показывать доску агентов» на странице Plugins.
- **Нет звука** — сервер не перезапущен после обновления (`/agents-board/chime.wav` отвечает 404)
  или звук едет не в тот аудиопуть: переключите «Звук через» и нажмите «Проба».
- **Правил client.js — на доске ничего не поменялось** — рантайм читает копию профиля: запустите
  `install.ps1` заново, затем F5 (правки host-половины — с рестартом сервера).
- **Удалил мастер-папку** — сервер не пострадает: рантайм читает копию профиля. Верните копию
  запуском `install.ps1` из любого места, где лежит папка.
- **Сбросить layout окна** — очистите ключ `agents-board.layout` в localStorage страницы.

## Файлы

| Файл | Роль |
|---|---|
| `package.json` | манифест бандла: `dsh.bundle.patch`, `dsh.client` (platform + inject), экспорты `.` и `./client` |
| `host.mjs` | host-половина: Config-схема + маршруты chime/devices |
| `client.js` | клиентский бандл: колонки, счётчики, карточки, кнопка, тосты, оповещения |
| `cordis.patch.yml` | overlay-патч бандла (`id: agents-board`, `config:` с дефолтами) |
| `deps\` | вендоренные schemastery + cosmokit (создаёт install.ps1) |
| `install.ps1` / `install.bat` | установка: deps → чистка легаси → pack → официальный `dsh plugin add` → точечное удаление артефакта |
| `uninstall.ps1` / `uninstall.bat` | удаление: официальный `dsh plugin remove` + чистка легаси |
| `PLUGIN-FAILSAFE-REPORT.md` | отчёт об отказоустойчивости и рецепт порта для остальных плагинов |
